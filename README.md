## 📖 这是什么

这是一个为角色扮演补上“日常生活背景”的 AstrBot 插件。Ta不再只是被叫到才出现的回复者。

清晨会随着今天的主题醒来，看看天气，想想要不要出门；午后可能摸鱼、观察群聊、补一点能量；夜深时会根据疲惫、睡眠债和打扰程度，慢慢进入浅休息、浅睡眠或深度睡眠。

这不是一张固定日程表，而是一套持续演化的生活系统。Ta有自己的心情、穿搭、关系印象、地点记忆、生活事件和一点点主观小心思。聊天发生时，这些会作为隐藏生活背景参与判断，让回应更像从Ta正在经历的日子里自然长出来。

私聊主动联系也会顺着生活节奏变化：“私聊联系参考间隔”用于安排重新考虑联系的时机，忙碌、困倦时延后，日程转场时可提前留意。主动说过一轮后仍会继续生活与观察，结合真实交流、未完的话题和新的进展决定是否再联系。“私聊频率”同时供 daily_share 和 B站账号活动参考；私聊、日常分享与已绑定身份的 B站私信共用实际收发记录，连续联系未获回应时逐步放缓，对方回应后重新计算。暂时没话说不会积累成负面反馈；明确的拒绝、睡眠和免打扰仍会约束联系。

## 🌟 核心能力

### 1. 🕰️ 朝夕流转：自主生活日程

* **每日生活背景**：结合人设、天气和近期经历，生成当天主题、心情、穿搭、时间轴和生活小事件。
* **日历与季节事实**：聊天与日程共用日期、星期、节假日、节气和季节背景，日常活动与穿着结合实际天气判断。
* **启动与跨日延续**：首次启动自动补全当天生活，以每日生成时间划分业务日，让凌晨的生活自然接续。
* **周计划与探索**：围绕兴趣、记忆和目标形成周计划，也可适时安排本地探索、短途旅行或周边游。
* **邀约与临时安排**：可接受、拒绝或商量改约，把聊天中新确认的同行、见面和准备事项纳入后续日程。
* **共同活动行前联系**：根据准备、路程和最近交流判断联系时机，例如观影前商量吃喝、出门前确认会合。
* **时间轴与实际行动**：安排会随执行推进，临时变化只调整尚未发生的部分；换装、用餐和媒体交付等结果以执行证据确认。
* **持续自主生活**：启用生活实况与虚拟生活动作后，Ta会在后台自行选择休息、喝水、做饭、学习、家务等活动，并保留进度。
* **连续身体需求**：体力、困倦、疲劳、饥饿、口渴和社交电量会随时间与活动变化，影响之后的生活选择。
* **身体不适与恢复**：可逐渐觉察日常不适或生病感，调整活动和交流节奏，恢复过程跨日延续；只表达生活感受，不虚构医学诊断。
* **运动与餐食**：结合天气、体力和近期负荷安排运动；采购可衔接前置移动，完成后入库，做饭按实际库存扣减食材，再结算进食。地点、食材和执行结果共同决定行动能否完成，不能只等时间过去。
* **地点与出行**：通过高德地图选择真实地点，结合距离、天气、体力和可用时间规划交通方式与路线。
* **长期目标与成长**：从兴趣和经历形成目标，记录练习、作品与阶段成果，让未完成事项跨日继续。
* **持续物品与创作**：书籍、物品和草稿保留位置、数量、状态与进度，数字作品可继续创作并查看历史版本。
* **共同经历**：一起看电影等活动可保存准备、暂停和继续的进度，跨日或重启后仍能接上。
* **静默期间仍生活**：静默时段暂停自发打扰和例行衣橱判断，身体变化与内部生活继续运行，正常聊天、约定联系和已有媒体任务保持可用。

### 2. 🧠 心绪小雷达：状态与注意力

* **持续变化的状态**：体力、心情、忙碌度、社交意愿、无聊、睡眠和注意力随生活变化。
* **消息关注判断**：结合当前活动、关系和消息重要性，决定是否关注、回应或继续观察。
* **看见与没看见**：区分未留意和看见后未回应，保留主观感受，让之后的态度有迹可循。
* **分层情绪**：短时情绪、当日心境和关系感受分别延续与淡化，让情绪变化具有层次。
* **状态记录与巡检**：可以查看变化原因；生活稳定时减少重复判断，活动变化时及时更新。
* **聊天里的生活感**：后台保留完整身体状态与行动记录，聊天只带入当前场景、衣着、简短感受和本会话未完约定；详细日程、天气和生活资料随本轮语义召回。感受复用已有状态刷新，不额外调用润色模型，也不从分数编造经历。
* **控制生活注入量**：本轮动态生活背景最多 6,000 字符，并受 5,000 估算 token 预算约束；按完整记录取舍，保留时间、计划和事实边界。该上限不包含原有人设、聊天历史、用户消息及工具定义；调试日志分别记录各部分字符量。

### 3. 👗 今日穿搭：不是换装按钮，是生活判断

* **场景适配**：结合天气、活动、身体状态与可穿衣物选择完整搭配，区分当前穿着和稍后准备，合适的衣服可以继续穿。
* **准备动作落地**：对话中的行动意愿可以及时进入生活复核，邀约和聊天约定中的换装交给生活执行流程；执行成功后同步当前外观、衣橱穿着和行动记录，未变化时如实保留当前穿搭。
* **外观保持连续**：聊天、面板和图片共用当前穿搭；鞋履、外层和随身物品分别记录穿着、携带或放下状态。
* **历史穿搭回现**：保存实际外观变化，可查询昨天、昨晚或指定时刻的造型，回现不改变当前穿着。
* **跨日延续与自然变化**：未换装时延续上一套外观，新造型结合近期穿着调整，兼顾复穿与变化。
* **服装与妆发分开管理**：套装、上装、下装、鞋袜、配饰、发型、妆容和美甲均可独立学习与搭配。
* **视觉衣橱学习**：从图片中识别可靠单品与造型，保存为衣橱候选；已有衣物的用途资料在后台分批完善并缓存。
* **创意衣橱生成**：支持按自然语言需求后台生成造型。文生图不使用角色参考图，图生图使用当前角色参考图；图片经识别核对后自动收入衣橱，衣物记为已拥有，无需手动确认。
* **自主补衣与审美**：缺少适合当前场景的可穿整套搭配时，主动评估需求、生成、识图和入库，再重新选装；已有可用衣物时优先重选。实际缺衣与审美尝新分别评估，避免同一需求重复生成；优先使用角色图生图，缺少参考图或编辑通道时改用文生图。
* **穿护与反馈**：记录衣物归属、穿着和洗护状态；结合跨日穿着经历与用户反馈逐渐形成审美，生成入库后仍需实际采用才改变当前穿搭。

### 4. 💬 聊天余温：关系、记忆与自然靠近

* **关系档案**：积累称呼、近期印象、互动经历和关系叙事，让不同对象拥有各自的相处方式。
* **第一人称记忆**：Ta参与的经历以自身视角记录，人物称呼、身份和关系结合人设与明确线索保持一致。
* **话题新鲜度**：根据相关度、情绪和兴趣保留话题余温，之后遇到相关内容时可以重新想起。
* **随心回复**：结合最近双方交流，选择现在回应、继续观察或等待后续消息。
* **闲时续话**：会话安静后，结合刚才的话题和当前生活判断是否自然续一句；收到新消息会重新计时。
* **私聊回访**：可选开启，根据关系和生活状态自然想起某个人，联系前核对近期交流与当前安排。
* **主动交流分寸**：发送前检查话题衔接、重复追问和打扰程度，出现新消息或情境变化时取消过期内容。

### 5. 🫧 聊天表达

* **统一开关**：可统一管理短句风格、连续消息收束、分段、标点清洗和发送间隔；关闭后直接发送模型原文。
* **自然长短**：日常闲聊偏向简短，解释和情绪支持保留必要内容，可配置自己的表达风格。
* **持续表达学习**：从角色自己已经发出的表达、明确偏好、真实互动反馈和有内容依据的生活见闻中逐步形成语气、句式节奏、情绪与幽默、叙述和话题承接等表达经验；经验先以低强度尝试出现，经过不同情境的真实反馈才稳定，效果变差会暂时收敛，纠正后从新版本重新积累。
* **表达边界**：角色自己的语言风格、某段关系的通用偏好和具体情境习惯分层保存；私聊对象的偏好不会变成角色人格，也不会把私聊证据带入公开分享。重启后可从已记录的发送回执继续完成反馈评估。
* **连续消息统一回复**：支持先文字后图片、先图片后文字和连续多图，按发送节奏整理为完整话轮；群聊可单独开启。
* **自然分享**：顺着话题与关系分享生活小事，让主动表达有当前经历作为依据。
* **语义分段与清洗**：按语义和自然停顿分段，清洗标点，保留原文信息；分段模型可独立配置。
* **主动语音**：开启后，主动消息结合话题、关系和收听情境选择文字或语音。
* **取回转图原文**：长回复被 AstrBot 转成图片后，可按需通过 QQ 合并转发取回暂存的文字版。

### 6. 🌙 夜晚收束：睡眠、复盘与偏好学习

* **睡眠分层**：结合精力、睡眠债和消息打断，在浅休息、浅睡眠与深度睡眠之间变化。
* **每日复盘**：夜间或次日生成前整理当天经历、记忆点、偏好与后续事项。
* **偏好学习**：从聊天和生活经历中逐渐形成稳定偏好，合并同义内容，影响后续安排。
* **跨日生活事件**：让未结束的小事与关注自然延续，第二天仍记得之前发生了什么。
* **反思与日记**：根据已保存的事件和反馈形成第一人称日记，有充分依据的反思才沉淀为长期认识。

### 7. 🗃️ 记忆小抽屉：结构化数据

* **生活记录**：保存日程、天气、穿搭、状态、关系、地点和事件，也记录餐食、家务、运动与物品变化。
* **计划与约定**：统一保存周计划、备忘、邀约和未来承诺，供日程与聊天按需读取。
* **相关记忆召回**：结合全文、语义与经历关联选取相关记忆，支持跨日追问；可复用 AstrBot 已配置的向量模型。
* **历史索引补全**：后台逐步补齐历史语义索引，聊天可先使用已有索引与本地检索。
* **记忆来源与纠正**：区分历史经历和当前事实，明确纠正后优先使用更新的认识；需要时可分页回看已留存的原话。
* **后台记忆整理**：整理同一经历的前后变化，让普通琐事逐渐淡出，同时保护重要经历、纠正和未完成约定。
* **回复效果学习**：结合用户后续的真实反应记录表达效果，为之后的相处提供参考。
* **状态一致性**：聊天、自主生活与面板读取一致的当前事实，并发更新时保护较新的状态。
* **任务恢复与配置切换**：支持后台任务续跑、待交付媒体恢复和配置热切换，已受理的异步图片继续查询原任务。
* **运行观察与缓存**：面板可查看调度延迟、模型耗时、失败数和接口报告的缓存命中比例；后台等待期间仍可聊天。
* **自动整理**：按保留策略清理旧记录与无用素材，控制存储和上下文规模。


**经历、回忆与自主学习**

经历、日记、阶段回忆与阅读感受由后台生活调度自主整理，需要时通过聊天和工具回看当时的对话或资料原文。仪表盘保留前台、衣橱、表情和设置入口，浏览与记忆能力继续在后台运行，无需维护独立页面。没有新经历或阅读理解时留白；来源被纠正或失效后，相关衍生回忆停止参与读取，后台依据新版本重新整理。

- 关系关联沿实际记忆中的人物、地方和事件建立，保留具体来源和发生时间；不会因为名字相似就跨会话合并。
- 阶段回忆逐层整理为周、月、季度、年；回忆较多时分批归纳，上层继续保留底层来源编号。原话独立保存，聊天压缩后仍可按会话和时间分页找回；升级前已经丢失的原话无法凭空恢复。
- 日记复用已有日记档案，由角色决定是否有想留下的片段，不要求每天写；过去的事实与现在的感受分别理解，不自动发送给用户。
- 书架保存真实文字与出处，每份最多 2 MiB。角色可从自身学习需要出发查找资料或读取来源链接，取得正文后自动归档并衔接阅读；自主查找的资料归属角色自身，工具收录沿来源会话保留，无需人工分配。只取得搜索摘要、未取得正文或没有阅读回执时，不计为已经读完。
- 自主行动模型可从自己的书架选择阅读、续读、重读或暂时不读，不需要手填兴趣。只有真实读取原文且有可核对引用的理解落库后，阅读进度才推进；暂停、中断、模型失败不会记为读完，也不把读过等同于掌握。
- 阅读手记保留资料理解、自己的想法、未解问题和前一条手记，后续选择可参考这些实际变化。资料原文检索使用语义理解，返回片段编号与引用，支持分页继续查找。
- 新整理任务沿用「记忆模型」，留空按现有默认模型逻辑；行动选择仍使用原自主生活行动模型。后台调用间隔是资源保护，不是角色的写作或学习目标。
- 新资料表和阅读记录纳入长期记忆备份/清理范围，原话遵循聊天保留期，有长期记忆来源引用的原话继续保留。数据库结构为 schema 32。

可用工具：`life_memory_search` 的 `graph/chapters/diary/originals` 模式与 `life_knowledge` 的 `list/search/read/note/notes/import`。这些资料按需读取，不追加到每次私聊的全量隐藏上下文。

### 8. 🎙️ 声音、影像与表情：把生活说出来、拍下来

* **GPT Image、Gemini、Grok 生图**：支持文生图与图生图，可结合角色形象、当前穿搭和场景生成生活照。通道顺序、模型、尺寸、比例和超时均可配置。
* **自然分享照片**：角色可顺着话题、关系和眼前生活主动分享有画面价值的瞬间。
* **真实换装与图片试穿**：实际换装照采用已保存的当前造型；临时试穿和图片创作可使用指定造型，保持生活状态独立。
* **生活套图**：默认生成 3 张、最多 10 张独立照片，保持人物、穿搭、场景和光线连续，支持按位置重拍。
* **人物身份参考**：结合人设、关系档案和参考图保持角色与好友身份，合影分别绑定双方外貌及穿搭。单张合影、合影套图和新建视频首帧共用好友身份解析：工具省略对象时，仅在私聊发送者与参考档案唯一匹配时自动补齐；身份不明则返回缺失参数，已选对象随任务锁定。
* **合影视频**：支持让已有合影动起来，或重新生成双人首帧后拍摄；视频失败时可保留并发送已生成的合影。
* **Grok 视频生成**：支持手动填写模型名称、首帧参考及 480p/720p/1080p 清晰度，后台生成后发送；未明确指定时沿用配置时长。静态首帧与视频动作分别规划，避免把连续分镜用于生成单张首帧。
* **Gemini 原生视频理解**：普通视频支持完整画面与声音理解，复用模型地址和 Key，支持 MP4/MOV/WebM；插件内联上限为 15 MiB，并非 Gemini 能力上限。
* **视频总结与多图学习**：其他模型和 B 站长视频保留关键画面与转写流程；视频总结及视觉衣橱学习均可后台执行。
* **媒体后台交付**：生图、改图、套图和视频等待期间可继续聊天，后续图片或表情包不会替换已提交的参考素材；支持异步查询的图片任务可在超时或重启后继续查询。
* **火山引擎语音合成 2.0**：支持预置音色与声音复刻，结合表达情绪调整语音。API Key 和音色 ID 在插件中填写，声音上传与训练在火山控制台完成。
* **语音智能切换**：结合当下状态和对话判断是否适合说出口，再结合发送节奏选择语音；判断模型和超时可独立配置，与语义分段始终分别调用，同一模型也不合并；合成后复核会话，避免发送过期回复。
* **实时通话（可选）**：支持 WebSocket 实时语音和 veRTC AI 音视频通话，沿用当前人设、关系与生活背景，并在结束后保存转写。
* **通话接入与扩展**：需将 6186 网关映射为可访问的 HTTPS 地址并配置 `public_url`，语音与 RTC 凭据分别填写；可按配置开放插件/MCP 工具及官方联网，受支持模型可启用唱歌。
* **表情与动作**：结合话题和情绪选择表情，轮换近期使用过的素材，让普通回复和主动交流更有表现力。
* **工具状态表情**：OneBot/NapCat 可在原消息上显示耗时工具的处理中、成功或失败状态。

## 🚀 快速开始

1. **📦 安装并启用**
   - 在插件市场安装 `astrbot_plugin_daily_life`。

2. **⏰ 设置生成时间**
   - 默认是 `07:00`。
   - 可直接说“把每天生成时间改到 07:30”，由工具更新。
   - 这个时间既是每日生成时间，也是业务日边界。

3. **🧠 选择模型**
   - 生成模型负责完整日程、周计划和未单独指定的任务；“地点预选模型”只负责生成日程前整理地图查询意图，留空时使用 AstrBot 当前默认模型。
   - 穿搭、状态、复盘、邀约、图片理解、表情识别、记忆、随心回复和闲时回复都可以单独选择模型。
   - 视频提示词提取、自动表情选择、自主生活行动、共同活动联系、记忆重排和任务失败表达也可独立选模；选择同一模型时仍分别调用。
   - 指定模型失败时会临时使用当前默认模型继续；指定模型恢复后会自动回到指定模型。

4. **🌦️ 配置天气和称呼**
   - 居住地由高德地图解析为天气城市和“家”的坐标，会影响天气、日程、穿搭和出行。
   - 修改居住地后会自动重建当前周计划、天气和当天生活背景；旧城市记录仍可作为历史回看，但不会继续充当当前附近地点或日程素材。
   - 如果平台无法稳定获取昵称，可在本地用户称呼映射里补充 `用户ID:称呼`，它会用于聊天记忆、邀约、备忘录、参考私聊、MemOS 和面板展示。

5. **🌱 生成第一天**
   - 直接说“重新生成今天”即可生成当前业务日完整生活背景。
   - 直接问“今天安排是什么”“Ta现在在干嘛”即可查询。

6. **🖥️ 打开仪表盘**
   - 在网页管理后台的插件详情页进入 `dashboard`。
   - 可查看状态、世界记忆、生活复盘、近期演化，也可以直接调整设置。

### 🔐 权限与隐私

- 普通生活状态、今日日程和天气可以正常查询；跨会话历史、世界记忆、偏好、生活事件、配置概览、每日复盘和存储统计只允许 AstrBot 管理员查看。
- 清空数据、重生成日程、修改每日生成时间和 B 站登录管理只允许 AstrBot 管理员执行；换装、刷新状态、地图路线、邀约、备忘和视觉衣橱等会改变或暴露角色生活信息的动作，仅允许管理员或私聊会话使用。
- 这里的“私聊会话”按消息场景判断，不等同于主人或联系人白名单。插件同时服务多个私聊联系人时，他们会共同影响同一角色的全局生活状态；需要限制使用对象时，应在 AstrBot 的平台接入或权限配置中控制联系人范围。
- 承诺按创建会话隔离。普通用户只能查看和修改当前会话创建的承诺；旧记录若没有来源会话，只允许管理员维护。
- 聊天模型只负责提出结构化生活动作，插件会再次执行权限、归属、参数和状态校验后才提交；数据库迁移、事务、任务恢复、媒体投递和权限判断始终由确定性代码完成。
- 正常运行建议使用 AstrBot 的 `INFO` 日志并关闭 trace。需要排障时再临时开启 `DEBUG`，排障结束后及时恢复，避免聊天、地点、关系和日程上下文长期写入日志。

### 🎧 安装本地 ASR 依赖

1. 打开 AstrBot 管理面板，在左侧进入 **更多 → 平台日志**。
2. 点击平台日志右上角的 **安装 Pip 库**。
3. 在“库名”输入框中填写：

   ```text
   funasr>=1 modelscope>=1 torch>=2 torchaudio>=2
   ```

4. “强制 PyPI 软件仓库链接”可以留空；如需使用自定义镜像，再填写对应地址。
5. 点击 **安装**，等待平台日志显示安装成功后重启 AstrBot。
6. 本地 ASR 模型会在第一次转写时自动准备；准备失败时插件会继续使用必剪转写。

| 你可以这样说 | 会触发的能力 |
| :--- | :--- |
| “下午一起去看电影吧” | 判断邀约是否能打断今天的计划，并决定接受、改约或合并进后续日程 |
| “Ta现在在干嘛？” | 查询当前状态和正在发生的时间轴 |
| “今天安排是什么？” | 查询当前业务日完整日程、天气和穿搭 |
| “看看本周计划/世界记忆/最近历史” | 查询周计划、世界记忆、历史摘要等 |
| “重新生成今天，今天少出门” | 按补充要求重新生成当前业务日 |
| “保持日程，只换一下现在的穿搭” | 保留日程并更新穿搭判断 |
| “你这身适合出去玩吗？” | 结合当前穿搭、天气和外出安排判断是否合适 |
| “今天适合出门吗？” | 结合天气、日程、地点倾向和当前状态回答 |
| “今晚早点睡吧” | 作为聊天记忆、承诺或生活倾向被参考，不需要硬性的睡觉指令 |
| “把每天生成时间改到 07:30” | 更新每日生活背景生成时间 |
| “明天记得去超市买牛奶” | 写入明日备忘或未来承诺 |

## 🌐 联网搜索

插件提供一套独立于 AstrBot 默认网页搜索的联网能力：Tavily 负责网页搜索、正文提取、站点映射、站点抓取和研究任务，Grok 只负责 X 平台原生搜索。直接用自然语言说明要搜索、核实、读取或研究的内容，聊天模型会选择合适的工具。

### 1. 🔑 准备 Tavily 密钥

1. 在 [Tavily 控制台](https://app.tavily.com/) 创建 API Key。
2. 打开插件设置的“联网搜索”分组。
3. 在“Tavily 接口密钥”中填写一个或多个 `tvly-...` 密钥，不要添加 `Bearer` 前缀。
4. 开启“启用联网搜索”并等待设置自动保存。

Tavily 密钥只从 `search_config.tavily_api_keys` 读取，不会读取 AstrBot 自带网页搜索中的 Tavily 密钥。填写多个密钥时，每次创建 Tavily 请求会按顺序轮换；轮换用于分摊调用，不代表某个密钥失败后会自动改用下一条重试。启用本插件联网搜索后会自动移除 AstrBot 默认网页搜索工具，因此需要网页能力时应先填好 Tavily 密钥再开启。

“X 平台搜索”模型不是 Tavily 普通网页能力的必填项：不配置时，Search、Extract、Map、Crawl 和 Research 均可正常使用；配置支持 Grok 官方 `x_search` 的模型后，才可使用 X 搜索和 `both` 混合搜索，深度网页搜索也可用该模型规划补充查询。

### 5. 🧭 Quick 与 Deep

`quick` 用于单个问题，首轮使用 Tavily Fast Search，一般只执行一次主查询；向聊天模型回填最多 2000 字、5 条证据。适合当前事实、单条新闻、简单资料和普通问答。

`deep` 用于需要多来源核验的问题，首轮使用 Tavily Advanced Search。首轮证据不足且已配置搜索模型时，模型会规划独立的补充问题，并在剩余总时间内并发执行；补充查询总数受“补充搜索数量”限制，取得强证据、没有新增来源或时间不足时会提前停止。未配置搜索模型时，Deep 仍会完成一次 Tavily Advanced Search，但不会生成补充查询。Deep 向聊天模型回填最多 6000 字、8 条来源。

模型第一次调用时应提交一个完整问题，不需要一次生成多个近似搜索。工具结果会返回 `quality`、`missing_aspects`、`search_guidance`、`queries_executed` 和 `session_id`：证据为 `strong` 且没有缺失项时应停止；只有仍有缺失、来源冲突、用户追问或明确的新问题时才继续。

### 6. 📅 搜索来源、日期和参数

`source_scope` 决定来源：

* `web`：只使用 Tavily 网页搜索，也是默认值。
* `x`：只使用 Grok 官方 `x_search`，不会回退到 Tavily 网页。
* `both`：并发执行 Tavily 网页搜索和 Grok X 搜索，合并内容与引用。

日期限制针对**网页发布日期**，不代表事件发生日期。`time_range` 只在用户明确要求近期内容时使用，支持 `day`、`week`、`month` 和 `year`；`start_date`、`end_date` 使用 `YYYY-MM-DD`，填写后优先于相对时间范围。查询旧事件时不要随意使用 `year`，否则会排除更早但关键的原始来源。同一天的开始和结束日期会在发送给 Tavily 时自动扩展，避免 Tavily 拒绝相同日期。

其他 Search 参数：

* `topic`：`general` 适合一般资料，`news` 适合新闻，`finance` 适合金融信息。
* `include_domains` / `exclude_domains`：优先或排除指定域名；Tavily 精确限定站点应使用域名列表。
* `country`：只在 `general` 主题下用于国家或地区偏向。
* `include_raw_content`：需要核对页面正文时返回清洗内容，会增加结果长度和调用消耗。
* `include_images`：返回相关图片；`include_image_descriptions` 在此基础上请求图片描述。图片结果会单独返回 `images`、`image_quality` 和 `image_guidance`，不与文字证据质量混用。
* `auto_parameters`：允许 Tavily 根据问题自动选择部分搜索参数，适合边界不明确的复杂问题。
* `exact_match`：只保留包含查询原文的结果，适合精确短语，可能明显降低召回率。
* `platform`：主要用于 X 平台范围提示；Tavily 网页站点限制应使用 `include_domains`。

### 7. 🕸️ Extract、Map 与 Crawl

图片搜索取得文字来源但没有可用图片时，插件会在同一总时间预算内自动读取最多两个高相关 Tavily 页面补充图片，不需要模型重复发起多个近似搜索。工具结果包含图片后，下一步应直接调用 `send_message_to_user` 发送，不要继续重复搜索。

`life_web_fetch` 读取单个普通 URL 时优先调用 Tavily Extract。正文提取失败后，会在同一总时间预算内自动执行 URL 定向 Search：`mode=page_extract` 表示确实取得页面正文，`mode=search_fallback` 表示只取得相关搜索资料，后者不能表述为已经逐字读完原文。

批量 URL、指定相关性问题、要求图片、favicon 或特殊格式时会使用批量 Extract。每个地址最多返回 1 至 5 个相关片段；成功内容放在 `results`，失败详情保留在 `failed_results`，不会因为部分成功而丢失失败原因。

`life_web_map` 只发现链接，可使用路径和域名的包含/排除规则控制范围。`life_web_crawl` 会继续读取页面正文，支持相同筛选规则、图片、favicon、`basic`/`advanced` 提取深度以及 `markdown`/`text` 格式。只想留在当前站点时应明确要求不跟随外部域名。

### 8. 🔬 Research 后台任务

Research 采用后台轮询，不阻塞 AstrBot 主事件循环；任务同时写入生活插件已有的可恢复队列，插件重启后会按原会话恢复未完成任务：

1. `life_web_research` 创建任务并返回 `pending`、`task_id` 和 Tavily `request_id`。
2. 插件按“研究状态轮询间隔”在后台检查任务状态。
3. `life_web_research_status` 使用 `task_id` 返回 `pending`、`completed`、`failed`、`cancelled`、`error` 或 `timeout`。
4. 任务完成前不能声称报告已经生成；完成后再依据研究输出和引用回答。
5. 研究任务绑定创建它的会话；其他会话即使拿到任务编号也不能读取报告。

Research 支持 `mini`、`pro`、`auto` 模型，`short`、`standard`、`long` 输出长度，`numbered`、`mla`、`apa`、`chicago` 引用格式，域名包含/排除以及可选 JSON Schema 结构化输出。

### 9. 🗂️ 结果、缓存与日程灵感

每条用户消息建立一个搜索会话，共享“搜索总超时”和已有证据。查询词与参数完全相同时直接复用同轮结果；同一搜索上下文已经取得强证据时，会停止没有新增目标的重复搜索。跨消息的完全相同查询按 TTL 缓存，缓存键包含搜索深度、来源、最终日期、域名、图片和其他实际参数；同时发生的相同搜索或网页读取只执行一次上游请求。失败结果不写入缓存，模型提出不同查询或不同参数时不会被普通缓存阻止。

搜索日志会显示深度、范围、最终日期、引擎、来源数、耗时和查询内容。纯网页结果显示 `Tavily`，纯 X 结果显示 `Grok`，混合结果显示 `Grok+Tavily`；缓存命中会在工具结果中标记 `cached=true`。

开启“日程使用联网灵感”后，今日生活和周计划只接收带可核验来源的结果：弱证据直接忽略，部分证据只作为生活背景灵感，强证据正常参考。周计划的搜索与生成共用同一操作锁，避免并发操作重复搜索。

## 📺 B站自主浏览与账号互动

Ta 会结合自己的兴趣、人设、当前日程、精力、心情和未完成事项，决定要不要刷一会儿B站。内容来自自主兴趣搜索、登录账号关注的 UP 主和发现流，可以没兴趣、暂缓、看一半退出，也可以改天续看。生活决策可以在休息时明确选择刷B站，并立即进入一次浏览评估；登录、资源和正在处理消息等条件仍会影响是否开始。账号关注列表只提供内容来源，不直接成为角色的喜好。例行检查只提供考虑机会，不要求到点观看或分享。

在「设置 → B站」配置开关、浏览决策与感受模型、评论弹幕参考和每日浏览上限，视频自动总结设置也归入该组；浏览决策与感受模型留空使用当前默认模型。兴趣由人设、已有自身兴趣和实际浏览经历逐渐形成，无需填写兴趣词或 UP 主 UID；每日上限不是必须完成的配额。管理员需先在私聊使用 `/B站登录`，浏览前会验证登录态，未登录或登录失效时暂停浏览与续看，不回退到匿名浏览。关注列表自动分页读取并缓存，账号切换或登出后清除对应缓存。字幕或接口受限时会退避，不绕过访问限制。

内容优先读取实际字幕，缺少字幕时复用现有 Sight 音频转写和片段画面理解。字幕、观众评论弹幕与自己的感受分别处理；只有实际理解过的片段才推进检查点，下载了全片或全量字幕不算看完。聊天打断、生活事务优先、重启或离线时保留原进度，离线时长不会自动补成观看时长。

账号活动同样顺着生活发生：有空、有兴趣或有人找自己时才考虑，不要求每天收藏、评论、私信或发动态。七项能力共用现有登录和生活状态：

| 能力 | 实际行为 |
| --- | --- |
| 关注更新与熟悉 UP 主 | 自动分页读取登录账号关注的视频更新，积压进度可跨重启继续；从实际看过的内容逐渐留下、更新对 UP 主的印象，关注不自动等于喜欢 |
| 画面理解 | 当前片段内的预览分镜、实际解码画面、场景变化及字幕区域辅助理解；多 P 视频核对当前分 P，不将后面的画面算作已看 |
| 收藏与重看 | 使用账号中的真实收藏夹，按内容决定收藏、取消收藏或重新翻看；手动改变过的收藏状态会先核对同步 |
| 评论、回复与 @ | 读取视频评论通知，回读原楼层核实发送者及正文后决定是否回复；保留交流记录和分页进度，不将标题当成别人说的话 |
| B站私信 | 只回应已验证身份的B站相关私信；围绕真实浏览变化自主分享，也可在原私聊中请求发送B站相关内容；无关来信不回应，普通私聊正文和生活安排不带入；连续来信合并理解，有新经历时仍可再次自主联系，连续未获回应时逐步放缓，并与 QQ 私聊、daily_share 协调实际联系节奏，其他人的会话不混入 |
| 看直播 | 顺路访问账号关注的开播直播间，实际获取 FLV 或 HLS 短片段并理解画面或音频后再留下感受；线路失效时尝试备用线路，也可以发一条弹幕或离开，观众弹幕不是直播事实 |
| 空间动态 | 有值得公开的真实浏览感受时，用角色自己的账号发布文字动态；公开文案只使用公开素材 |

B站身份只需本人验证一次：在与你聊天的原私聊中发送 `/B站绑定 你的UID`，再用该B站账号将收到的整行验证码私信给角色账号；验证码十分钟有效。使用 `/B站绑定` 查看当前绑定，`/B站解绑` 解除。它仅用于确认跨平台是同一个人，不需要填写角色的兴趣或关注 UP 主。更换角色登录账号后，身份验证与账号互动记录分别保存。

「设置 → B站」可分别开启画面增强、收藏、评论、私信、直播和空间动态，以及设置互动次数、直播时长的资源上限。达到上限会暂缓，不会为了凑数互动。读取遇到登录失效、接口限制或风控时暂停、退避；画面理解需要已配置的视觉模型，音频理解复用 Sight 的 ASR。直播未取得可理解的真实片段时不累计观看。

账号写入前先保存发送记录，B站接受后记录回执。网络超时或运行中断留下“结果待核对”，后续分页核对实际评论、私信、动态或收藏状态，不直接重发；直播弹幕缺少可靠的本人回执时保持待核对。平台明确拒绝后，冷却并重新决定是否尝试，同一意图最多三次；失败不会记成已完成。来信可以暂放或决定不回应，不会阻塞新的交流和其他生活；评论楼层暂时无法核实时单独保留核实状态。公开表达只使用公开素材，私聊内容不进入公开文案。

你直接分享视频时，Ta 会尝试了解一段具体内容再自然接话；明确要求总结、摘要或笔记时，保留原有专业总结流程。读取不到时会保留不确定性，不凭标题猜内容。值得留下的感受和疑问才进入长期记忆；自主浏览的真实片段与感受也会进入统一生活决策，支持自身兴趣缓慢变化。同一视频的重复处理不累计为多份独立兴趣证据，不把用户的沉默当作负面评价。

分享仍经过已有联系判断，普通聊天、主动联系、私聊回访和 daily_share 都可以自然用上尚未分享的浏览感受，也可以决定暂时不聊。实际发送后按链接、标题或有具体依据的自然转述记账；转述核对失败会保存回执、后台重试并在重载后继续，待核对时暂不重复主动推荐。公开发动态与单条评论分别记录，已经准备好的分享也会重新检查发送事实。用户私聊分享的视频仅属于该会话，不进入公共动态或其他人的分享素材。浏览不产生必须发布的日报。

片段依据、进度、感受、疑问和账号活动回执保存在后台，由角色自主决定暂停、续看、暂放、放弃、收藏或重看，相关感受可在合适的聊天中自然提起。需要了解时可直接询问：`life_bili_browse` 支持查看记录、理解分享的视频与管理当前进度，`life_bili_message` 支持当前已验证身份的B站话题私信查询与发送，发送前统一确认语义范围。

## 🧠 MemOS 外部长期记忆

插件可以连接 MemOS 托管服务，把外部长期事实、偏好和纠错作为隐藏参考注入聊天。

默认是**只检索，不写入**：聊天前短暂等待 MemOS 返回相关记忆，超时或失败就跳过，不影响正常回复。开启精选同步后，只会把本插件已经判断值得长期复用的摘要、偏好、关系点、备忘录和记忆纠错异步同步过去，不会把每一轮聊天都塞进外部记忆。

内置记忆更像Ta自己的生活小抽屉，负责当天状态、关系印象、复盘和世界记忆；MemOS 更像可选的外部长记忆书架，适合和其他记忆系统共享稳定事实。

<summary><b>🧺 几个容易忽略的小设置</b></summary>

1. **每日生成时间**：同时决定生活背景生成时间和新一天的分界。例如设为 `07:00`，凌晨 `02:00` 仍延续前一天的生活。

2. **穿搭模型**：日程生成时的初始穿搭由生活生成模型决定；穿搭模型负责之后的实时选择与场景适配。

3. **创意衣橱**：在“生活背景 → 创意衣橱”开启；自主补衣还需开启生活实况、内部行动，并配置可用生图通道。

   - 手动可选文生图或图生图，图生图需要角色参考图和编辑通道。自动补衣优先角色图生图，条件不足时改用文生图，等待期间仍可聊天。
   - 结合天气、活动和自身审美按需复穿、重搭或补衣。自动生成经识别与复核后入橱，手动生成或导入可通过聊天确认纳入；入橱后不会直接换上，洗护中的衣物不可选穿。
   - 慢速生图通道建议将超时设为 `300` 秒以上。

4. **闲时回复**：群聊按沉默时间进入判断；私聊按参考间隔、生活余力和真实收发情况持续观察，由模型决定是否联系。「聊天表达 → 闲时回复」可设置独立裁定超时，默认整轮 30 秒，超时跳过本次。

5. **私聊回访**：开启后，后台结合关系、近期交流和当前生活寻找联系机会；与私聊续话、daily_share 共用联系节奏，可按陪伴需求调整。

6. **天气与地图**：在“生活实况 → 地点与出行”填写[高德 Web 服务 Key](https://lbs.amap.com/api/webservice/create-project-and-key)和现实居住地，天气与地点查询共用该地址。缺少配置时相关查询不可用，日程仍可使用估算的出行时间。

7. **模型自主安排**：主题、心情、作息和造型结合人设、天气与近期经历生成；联网资料只提供参考。

8. **日程补全**：面板可查看当天日程的生成状态；需要重新生成时，可在面板操作或直接说“重新生成今天”。

</details>

## 🧩 同作者插件

| 插件 | 关系 | 作用 |
| :--- | :--- | :--- |
| `astrbot_plugin_daily_share` | 姐妹插件 | 把见闻、热搜、心情、知识、推荐、图片、语音或视频自然分享到私聊或群聊 |

两个插件可独立使用，也可配合：生活插件负责“Ta正在怎样生活”，分享插件负责“Ta把路上拾到的见闻分享给你”。

联合使用时，分享插件可读取相关生活背景与表达偏好，复用生图、视频、语音和联网能力，无需重复配置图片通道。成功分享后的活动也可回传，延续到之后的生活与记忆中。

私聊、群聊与公开分享分别使用适合当前场景的信息，公开内容不会带出私聊经历。

daily_share 的活动回执支持按事件幂等补录，并按原始发送时间更新记忆和主动联系节奏。两插件对自动联系使用会话预约，发送前复核新消息及生活活动；普通聊天和用户手动要求的分享沿用原流程。

共同活动与物品的生活投影提供稳定事件编号和进展版本，便于 daily_share 识别同一件事的实际变化；仅更新时间、存储修订号或标点变化不产生新进展，公开分享继续按所属范围读取。

公开互动可保留原动态、评论及回复关系，并区分文字观察、已确认点赞和实际发言。文字观察不冒充看过图片或已经回应，点赞不冒充发出评论；同一事件重复补录只保存一份，不创建私聊记录。相关记忆通过只读接口按目标与公开权限检索，不额外调用模型。

daily_share 可选用生活插件的语音表达判断，默认关闭；启用后会调用表达判断模型，并复用其语音风格。

## 🧪 测试与回归

模型请求将固定规则与实时生活事实分开，稳定前缀并按需展开资料；相同证据的衣橱、记忆与图片观察可复用，场景、身体、天气或证据变化后重新判断。当前状态、约定和记忆边界优先保留。并发的相同生活快照和图片理解请求合并处理，图片缓存区分实际模型与本轮问题；缓存容量满时先清理过期项。视频完成索引可直接读取仍有效的识别结果，原生视频命中时可省去重复准备和模型调用，强制识别仍会重新处理。分段与语音仍独立调用，合法 JSON 代码块本地解包。运行统计记录实际输入、输出、缓存用量及重试、修复次数，接口未报告的用量保持未知。

在插件目录下运行 Python 回归、语法与配置检查：

```bash
PYTHONPATH=. pytest -q -o python_files='test*.py' tests
python3 -m compileall -q .
python3 -m json.tool _conf_schema.json >/dev/null
```

前端脚本检查：

```bash
find pages/dashboard -type f -name '*.js' -print0 \
  | xargs -0 -n1 node --check
```

回归覆盖日程与穿搭一致性、记忆隔离、后台任务恢复、消息投递和卸载清理等关键流程。

## 🌰 生活片段示例

**场景 A：出门前的小判断**

> 生活背景：午后有外出安排，天气微热。  
> Ta的判断：当前穿搭是轻便休时风，适合短途出门，只需要把头发重新扎好，不必整套换装。  
> 后续影响：面板记录“保持当前穿搭，轻微整理发型”，聊天时也会自然带出“正准备出门”的生活感。

**场景 B：群聊里的安静观察**

> 生活背景：Ta正在看综艺，注意力半开放。  
> 群聊消息：群里有人聊到一个Ta有点熟悉的话题。  
> Ta的判断：看见了，但当前话题已经有人接得很好，Ta暂时不插话，只留下“扫过但未回应”的主观痕迹。  
> 后续影响：几分钟后如果有人继续这个话题，之前扫过的内容可能被重新激活。

**场景 C：夜里慢慢睡去**

> 生活背景：今天社交消耗偏高，睡眠债也有一点。  
> 消息打断：普通消息不足以叫醒Ta，强相关消息可能让Ta短暂浅醒。  
> Ta的状态：从浅休息进入浅睡眠，再慢慢沉到深度睡眠。  
> 后续影响：第二天体力、心情和日程倾向会自然接续，而不是重新从满格开始。
