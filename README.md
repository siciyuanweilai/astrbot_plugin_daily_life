## 📖 这是什么

这是一个为角色扮演补上“日常生活背景”的 AstrBot 插件。Ta不再只是被叫到才出现的回复者。

清晨会随着今天的主题醒来，看看天气，想想要不要出门；午后可能摸鱼、观察群聊、补一点能量；夜深时会根据疲惫、睡眠债和打扰程度，慢慢进入浅休息、浅睡眠或深度睡眠。

这不是一张固定日程表，而是一套持续演化的生活系统。Ta有自己的心情、穿搭、关系印象、地点记忆、生活事件和一点点主观小心思。聊天发生时，这些会作为隐藏生活背景参与判断，让回应更像从Ta正在经历的日子里自然长出来。

## 🌟 核心能力

### 1. 🕰️ 朝夕流转：自主生活日程

* **每日生活背景**：生成主题、心情色彩、日程类型、日程基调、日程倾向、天气、穿搭、时间轴和当天小事件。
* **日历与季节事实**：普通聊天、主动回访和日程生成共用日期、星期、周末/调休工作日、传统节日、节气和季节上下文；节日只提供生活氛围参考，温度、衣物和洗漱等现实判断仍以实时天气、室内外场景和用户明确描述为准。
* **首次启动补全**：首次安装时，插件会在后台补全当前生活日；会先等待已配置的平台适配器连接，确保联系人和历史记录可查询。补全完成前的聊天使用防编造约束，不会假装已经有日程。
* **业务日边界**：以每日生成时间作为新一天边界，凌晨不会硬切到空白状态。
* **周计划延续**：根据人设、近期生活惯性、记忆、天气和目标自动维护主题、目标、每日提示和建议活动；它只作为每日生活生成的软参考，不是固定执行清单。日程会对近期地点做软轮换，并可在休息日、外出意愿较高或已有可靠计划依据时低频安排本地探索、短途旅行或周边游；没有明确目标城市时不会虚构跨城行程。
* **邀约打断**：用户提出邀约时，智能判断接受、拒绝、改约或合并进后续日程。
* **当天约定落地**：当天日程生成后新确认的同行、见面、出行和准备事项会再次经过人物归属、确认程度、地点与时间校验，只重排尚未发生的节点；改约方案、聊天承诺、批次记忆、会话行动项和工具新增承诺使用同一执行链路，临时失败可重试，重启后也会补偿尚未合并的当天安排。
* **共同活动行前联系**：已接受的邀约和普通聊天确认的共同安排，会在后台结合准备、路程、互动方式和最近交流判断是否需要提前联系及何时联系。临近观影可自然商量吃喝，出门前可确认会合或准备；已沟通、取消、改期和过期安排会再次复核，不固定提前几分钟发送，也不会把准备招呼当成活动已完成。
* **时间轴执行闭环**：活动会随时间轴在待进行、进行中、已完成、已跳过、已取消和已过期之间推进；跳过或取消必须有当天状态、互动或事件依据，夜间复盘只收束尚未结束的节点，不覆盖已有终态。复盘会保存结构化结果和整轮完成状态，并发更新或重启恢复时继续未完成阶段，不重复调用模型或覆盖较新的时间轴。
* **分层行动计划**：完整全天按生活跨度、活动复杂度和真实状态变化安排有意义节点，不设固定上限；系统仍会校验完整生活覆盖、节点密度、时间节奏和明显过大的时间空白。每个需要结算的动作保存类型、前置条件和效果，条件不满足时只重排尚未开始的局部计划。
* **真实动作回执**：图片、套图、视频等工具结果会确认对应动作并结算地点、穿搭和状态事实；内部数字生活的执行回执保留为模拟证据，失败或取消会留下下一轮局部重排依据。
* **聊天执行证据**：当前角色在同一会话已发送的明确完成表述，可以作为内部生活动作与非媒体计划承诺的模拟证据；校验对象、原文和状态后同步行动项。准备中、失败、用户自己的事项和未交付媒体不会误记完成，动作结算成功后才推进对应时间轴。
* **内部生活结算**：共支持 18 种显式动作。计划时段经过只会进入 `elapsed` 观察态，不会自动扣库存、改地点或改穿搭；休息、喝水、用餐、做饭、点餐、采购、移动、出行、工作、学习、家务、运动、整理仪容和换装 14 种内部动作在有执行证据或复盘确认后可以产生模拟回执。社交、聊天、拍照和视频 4 种动作仍需要真实回执。
* **持续自主生活**：启用生活实况和虚拟生活动作后，每分钟在独立后台任务中推进内部生活，不依赖收到聊天。模型结合人设、身体需求、兴趣、近期对话及约定选择行动；执行器记录开始、实际观测过程、暂停、恢复和完成，校验前置条件与库存后才提交回执。实际回复会进入当前会话证据，睡眠期间回应会记录短暂醒来并重新判断；不要求把会话加入日程参考。停机间隔不补造完成经历，重启从检查点恢复，同一动作不重复扣库存或累计进度。
* **统一生命内核**：身体、情绪、注意力、环境、社交接触、自主行动、目标和复盘共享一份版本化快照；真实聊天交换、行动回执和生活复盘写入有证据的事实账本，聊天上下文、状态刷新、自主判断和面板读取同一份连续性。其他记忆正文仍由记忆模块按范围和权限管理，不把推测写成经历。
* **持续的自身发展**：行动回执、事后判断和本轮数字笔记/草稿分别保存；练习时间不等于技能掌握。自己的兴趣、价值和边界凭已保存来源小步更新，未完事项沿同一编号跨日继续；身体、情绪、关系变化留下因果记录。完整自传和成果独立归档，当前上下文只读取有限摘要，成果接入原有长期记忆查询；清理体验沉淀时同步清除这些记录。
* **连续身体需求**：体力、困倦、疲劳、饥饿、口渴和社交电量按经过时间与实际执行的活动连续变化，睡眠、运动、用餐、喝水和持续交流有不同影响。模型负责感受、情绪和行动判断，不能直接覆盖这些累计数值；需求不按阈值强制触发动作。这是数字生活的简化模拟，不是人体或医疗模型。
* **自身长期目标**：从人设、已确认偏好和关注事项中形成最多三个当前目标，保存阶段依赖、阻碍、调整原因和行动证据。阶段按实际执行的练习时间累计，重排保留已有练习；练习次数和时间不等同于技能认证，也不代表模型参数已被训练。聊天、每日规划和面板共享这些记录。
* **静默期间仍生活**：静默时段只限制自发回访、闲时主动消息和主动通话邀请，身体变化、内部行动与状态巡检继续运行；正常聊天、已约定联系及媒体交付保留原流程。
* **运动与餐食闭环**：日程会结合体力、身体状态、天气、近期负荷和当天密度独立判断是否安排明确运动，不把通勤、购物或拍照走动机械算成锻炼。直接用餐不校验家庭库存，居家烹饪才按食材扣减库存并自动沉淀稳定食谱，点餐和外卖保持独立动作语义。
* **地点预选与出行校正**：完整日程先形成轻量活动地点意图，再通过高德地图选择真实候选，最终日程基于已确认地点生成；提交前仍会复核交通方式、预计用时、距离、出发地和路线来源。自动交通方式会综合真实路线距离、耗时、天气、体力和日程可用时间，不会固定优先步行，也不会仅因驾车更快就假定角色可以开车；用户明确指定的交通方式仍优先保留。公共交通会优先读取高德返回的结构化方案，区分公交、地铁和混合换乘，无法确认时才显示“公共交通”。同名地点结合提示消歧，预留时间不足时优先切换交通方式或顺延未来节点；网络、Key、配额或候选不可用时自动回到原始生成与最终校正流程。已确认的出行摘要会进入普通聊天和穿搭判断上下文，让后续回复知道出发地、目的地、交通方式、耗时和距离。

### 2. 🧠 心绪小雷达：状态与注意力

* **状态维度**：体力、心情、忙碌度、社交意愿、无聊值、摸鱼值、睡眠质量、观看状态和注意力开放度会持续变化。
* **消息打断等级**：不是每条消息都强行打断生活，而是结合当前状态、关系和消息重要性判断是否值得关注。
* **看见与没看见**：没看见不影响关系；看见但不理会留下主观痕迹，后续可能影响态度、回想或回避。
* **状态变化记录**：保存为什么想看群、为什么没回、为什么被打断、为什么切换成观察状态等内部裁定。
* **自适应巡检**：生活稳定时逐步延长模型检查间隔，日程节点变化时恢复及时检查，避免固定频率反复生成几乎相同的状态。
* **三层情绪状态**：短时情绪、当日心境和关系感受使用不同半衰期衰减；关系层只允许有证据的小幅变化，情绪只影响表达，不覆盖人物、时间或日程事实。

### 3. 👗 今日穿搭：不是换装按钮，是生活判断

* **穿搭适配判断**：外出、休息、天气变化、日程变化时，智能判断当前穿搭是否合适。
* **按变化触发**：只有时段、当前/下一项活动、天气温度区间、外出意愿或睡眠状态变化时才重新判断穿搭，普通状态轮询不会重复请求同一结论。
* **发生事实优先**：穿搭判断会区分数据库已有造型、已经发生的换装日程和实时生活状态；状态已经明确换上睡裙或外出服时，会把它保存为当前穿搭，不再被旧造型覆盖。判断说明不重复时间轴钟点，准确时间仍留在时间轴和证据中。
* **地点与穿着分开判断**：回家不等于立刻换成居家服；主体衣物在短暂停留或仍舒适时可以继续穿，鞋履、外层和随身物品按实际场景分别记录穿着、携带、待用或放下状态。主体服装不会重复夹带这些组件，聊天与图片使用同一份当前可见外观，已脱下或待用的物品不会重新出现在身上。
* **历史穿搭回现**：每次实际外观变化保存带时间的快照，同一时段多次换装也可保留；支持昨天、昨晚、前天、具体日期与时刻、上次穿搭等查询。旧记录仍可按已有时段历史回看，缺少记录或指代不明确时不编造，未记录的妆发细节不会借用当前造型，回现也不会改变当前穿搭。
* **跨日外观延续**：清晨尚未换装时沿用上一日最终实际外观；生成新一天的生活背景时，不把昨日具体造型当成今天必须照搬的素材。同日重新生成会保留已经记录的外观快照。
* **自主生活决策**：主题、心情色彩、穿搭风格、日程类型和发型都由模型结合近期状态、记忆、天气和目标自然生成，不再按固定清单抽签。
* **造型防复刻**：近期生活只提供聚合惯性，不把旧穿搭、颜色和发型反复当作生成素材；普通造型与近期记录高度重复时会在保存前单独重写，睡衣允许自然复穿，但连续多日仍是同一具体组合时也会触发调整，不改动已经生成好的日程和人物事实。
* **穿搭与发型分离**：穿搭正文只描述服装、材质和必要配饰，发型名称与发型细节使用独立字段保存和展示；同日强制重生成时，旧造型只参与重复检测，不会被当成必须延续的当前事实。
* **视觉衣橱学习**：可以学习用户发送、引用或明确提供的服装商品图、穿搭图、发型图、妆容图和美甲图；插件不会替用户搜索或抓取网页，图片来源地址只用于追溯。视觉模型会把可靠内容拆为套装、上装、下装、鞋袜、配饰、发型、妆容和美甲八类；自动搭配既可使用完整套装，也可组合独立单品，只有明确采用对应类别时才改变当前发型、妆容或美甲。同图按类别去重，未采用的候选不会自动写成“已经换上”。
* **创意衣橱生成**：生成请求提交后在后台执行，等待期间可以继续聊天。开启 `image_generation_config.creative_wardrobe.enabled` 后，可按本次自然语言需求直接生成生活化完整造型。手动生成支持文生图和图生图两种模式：文生图不使用角色参考图，图生图只使用当前角色参考图；每张生成图都会独立经过视觉识别，识别出套装或上装与下装组合后才写入衣橱候选，不会改变角色当前真实穿搭，也不会自动发送生成图。手动生成数量由本次请求决定，不读取联网灵感或固定风格池。
* **自主衣橱与审美**：根据居住地实际天气、活动和身体记录，优先保留合适穿搭、组合已有单品；确有缺口才在后台用角色参考图做图生图，完整衣物识别和用途复核通过后正式入库。套装、上装、下装、鞋袜、配饰记录拥有与穿护状态；发型、妆容、美甲作为独立造型管理。审美区分人设、自身跨日穿着经历和用户反馈，不将一次选择固化为永久喜好。
* **造型反馈闭环**：可以查看已学习候选并用自然语言反馈喜欢、不适合、太厚、颜色不合适或不要再使用；反馈由模型按完整语义调整候选分数与状态，只有稳定、可复用的意见才进入长期偏好。

### 4. 💬 聊天余温：关系、记忆与自然靠近

* **关系档案**：沉淀互动次数、近期印象、主观称呼、短标签、关系叙事和来源会话。
* **第一人称记忆叙述**：新生成的关系、会话摘要、群聊环境、消息留意、动作裁定和行为反馈会根据叙述主体选择视角；当前角色参与的经历使用第一人称，不通过前端正则或关键词替换历史文本。
* **人物事实一致性**：人物称呼、性别和关系按“本轮明确说明 → 当前人设 → 已保存人物线索 → 稳定背景”的顺序使用；本名、昵称和备注按关系档案对应，证据不足时使用姓名或中性称呼。日程、周计划、邀约、承诺、主动回复和合影规划只在存在明确人物线索时执行一次有界语义审计，修订只能落在原有文本字段，不能改动业务结构或数量。
* **心理新鲜度**：消息不会只按时间过期，会根据相关度、情绪、关系和当前兴趣衰减；后续同一话题可以重新激活。
* **同一会话轮次**：随心回复先决定当前要回复、观察还是等待；选择观察或等待后，闲时回复会沿用这一轮上下文，在会话真正安静后重新判断，不会把两套机制当成互不相关的回复器。
* **闲时回复**：会话安静一段时间后，先承接最近双方交流的话题、情绪和收尾，再结合生活状态与关系判断是否值得简短续一句；新的用户消息或 Bot 已发送回复会取消或更新原有等待任务。
* **主动消息衔接**：补全保存历史与当前会话缓存，保留自身上一句和引用关系；闲时回复与私聊回访发送前检查突然换题、重复追问和打断道别，接不上就暂不发送。到期承诺同样结合最近交流复核取消、改期和提醒时机，不为解释联系而拉长回复。
* **私聊回访**：可选开启。Ta会在私聊达到静默时间后，根据关系记忆和生活状态判断是否自然想起某个人；发送前还会核对带时间的最近消息、当前活动、状态、日程和约定，生成期间出现新消息或生活状态变化时会取消旧回访。
* **不抢正常聊天**：闲时回复只在沉默后触发，不拦截命令，也不替代原本聊天流程。
* **主动社交生命周期**：候选、考虑、等待、发送、互动、收束、冷却、中断和放弃均有显式状态；只有收益、时机和连续性减去打扰与不确定性后达到阈值，才允许发送，且成功送达后才提交记忆。

### 5. 🫧 聊天表达

* **统一开关**：`chat_style_config.enabled` 同时控制短句风格提示、四项参考长度、连续消息收束、模型语义分段、自然分段兜底、标点清洗和分段随机间隔。
* **短句风格软偏好**：`chat_style_config.casual_short_prompt` 只描述稳定的语气、节奏和展开尺度；它会被压成单行并限制长度，不覆盖本轮任务、事实准确性、情绪支持、平台或安全要求。已填写的个人风格偏好按原设置保留。
* **有证据的表达学习**：现有后台聊天总结会结合用户明确偏好或至少三次独立互动反馈，学习对应对象、对应场景的语气、短句节奏、话题承接及避免事项；一次感谢、沉默或角色自己的回复不会自动形成习惯。明确纠正可以修订原习惯，保留消息证据，不跨会话套用。学到的内容作为普通聊天和主动消息的软参考，不修改模型权重，不把所有回复强制缩短。
* **主动表达自检**：闲时续话和私聊回访在原裁定模型调用中检查最终文本是否承接话题、重复关心追问或不合关系分寸，缺少有效检查或检查未通过时暂缓发送；检查不占用普通聊天链路。
* **连续消息统一回复**：私聊同一用户短时间连续发送文字或图片时，按实际发送节奏自适应收束；支持先文字后图片、先图片后文字及连续多图，最终请求保留完整文字和按发送顺序排列的图片。单条消息只作短暂等待，续话会动态调整尾部停顿，收束等待受总上限约束；语义判断会参考完整话轮，不按消息条数或等待轮数强制接话。正在生成时补发图片会停止旧生成，交由包含参考图的完整话轮处理；命令、引用、语音、视频、文件和工具结果保持独立处理，群聊需单独开启且按发送者隔离。
* **自然分享**：可以顺着话题和关系分享有当前事实依据的小事，无需等用户明确询问；不把计划说成经历，不强插日常或打断倾诉。
* **主动语音**：开启“主动消息智能语音”后，闲时回复、私聊回访和主动承诺根据话题、关系及收听情境选择文字或语音，不再抽取概率。缺少明确语音意图时保持文字，语音失败时回退文字。
* **直接语义分段**：开启后，模型返回可直接发送的完整分段；模型原文中的显式换行是稳定边界，语义分段可以细分一行，但不会把相邻两行重新粘连。
* **完整优先**：自然分段兜底只依据显式换行、通用标点和参考长度，不识别特定句型。参考长度只影响表达和分段节奏，发送时保留全部内容，私聊回访也不会仅因超过参考长度而被拒绝。日常闲聊整轮保持简短，不因分条而扩写；必要的解释和情绪支持说完整。局部长句会增加必要的软分段额度，逗号等软停顿不会挤占后续句号、问号的强边界；分段数量仍是上限，不会强制凑满。未形成有效多段时仍保留原文单条发送，不在句内截断正文。
* **可中断发送**：多段发送期间收到新消息，会取消尚未发送的过期尾段；单条回复的累计模拟停顿最多 8 秒，避免长分段持续占用消息处理阶段。
* **独立分段模型**：`chat_style_config.semantic_provider` 留空时使用当前第一个聊天模型；可单独配置语义分段模型。
* **关闭即直发**：关闭“启用聊天表达”后，不再注入聊天表达提示或参考长度，也不做分段、标点清洗和分段间隔处理，模型原文按单条消息发送。
* **按需取回转图原文**：AstrBot 把长回复转成图片发送后，插件只在内存中暂存原文；用户之后需要文字版时，模型可调用工具通过 QQ 合并转发原样发送，不会在每张转图后自动附带文字。

### 6. 🌙 夜晚收束：睡眠、复盘与偏好学习

* **睡眠分层**：浅休息、浅睡眠、深度睡眠由能量、时间、昨日睡眠债和打断等级共同影响。
* **每日复盘**：夜间或次日生成前沉淀当天总结、记忆点、偏好点和可延续生活事件。
* **偏好学习**：从聊天、复盘、状态演化和邀约结果中学习稳定偏好，再影响之后的日程；启动后台与夜间复盘会用模型合并只是换了说法的同义偏好，穿搭、活动、社交、睡眠和地点等类别统一处理，重复观察只更新最近证据，不再叠加成越来越高的权重。
* **生活事件**：保存会延续几天的小事，让后续生活不再每天从零开始。
* **有证据反思与日记**：反思达到重要度和证据门槛后才可晋升为人格断言；第一人称日记只能引用真实事件、决策、反馈或回复效果记录。

### 7. 🗃️ 记忆小抽屉：结构化数据

* **每日记录**：日程、时间轴、天气、穿搭、状态和当天事件。
* **并发写入保护**：每日记录带版本号；天气、状态、穿搭和时间轴并发更新时会合并互不冲突的字段，同一字段出现新旧结果竞争时保留较新的版本，不再让旧模型结果整日覆盖。
* **状态日志**：体力、心情、社交意愿、睡眠和注意力变化。
* **世界记忆**：关系档案、地点档案、事件记忆、聊天摘要、群聊氛围和消息留意。
* **当前话题优先**：长期记忆、生活经验和外部记忆只选取与本轮消息相关的少量内容注入，避免旧话题挤占当前聊天。
* **可恢复任务**：每日刷新、夜间复盘和主动检查先写入持久任务队列，每项任务使用独立租约，长任务自动续租，失去租约时停止旧执行器；已经生成但尚未确认投递的图片、套图和视频会在插件重启后恢复发送。返回任务编号并支持查询的异步图片接口，还会保存已受理请求，超时或重启后继续查询原任务，不重新提交；套图各位置分别恢复。任务队列不允许从数据库执行任意代码。
* **配置切换**：保存配置先准备新服务，全部成功后才生效；失败时恢复原配置、调度器与语音服务。正在执行的任务继续使用原服务，新聊天使用新服务，不必等待旧媒体生成完成后才能应用配置。
* **一致性快照**：提示词所需的关系、事件、承诺、体验和当前事实会在一次数据库锁定及一次工作线程切换内读取；数据库工作线程使用受控隔离 Runner 执行批量读取，不依赖手动驱动协程，也不阻塞框架主事件循环。
* **跨时区缓存边界**：媒体、视听、反推、表情素材和上下文快照统一按真实时间戳判断有效期，在 UTC 容器和其他系统时区中不会提前删除或长期滞留。
* **语义相关召回**：可在“大语言模型”配置中选择向量模型，用于长期记忆、生活经验和表情候选排序；留空时使用当前默认向量模型，无需为插件重复配置密钥。未配置或临时不可用时会在短超时后回退到记忆模型，再不可用则保持稳定来源顺序；某类注入上限设为 `0` 时会严格保持为空。
* **回复效果学习**：普通 Bot 回复也会进入聊天记忆，并根据用户后续真实反应学习表达效果；没有后续反馈时不会猜测用户态度。
* **计划约定**：周计划、备忘录、邀约和未来承诺。
* **生活领域记录**：活动会话、食谱与食材库存流水、用餐、家务周期、运动负荷、路线缓存和会话行动项使用独立结构化表保存，并进入统一时间线；采购动作中的普通物品不会写入食材库存。已提交动作会幂等补齐缺失的专属记录，启动时也会修复旧版漏写数据和已完成烹饪遗漏的食谱关联。批次提炼出的承诺同步生成行动项，同一动作优先展示信息更完整的专属记录，日程替换后不再展示已经失效的模拟记录，真实回执继续保留。
* **稳定上下文预算**：生活实况按行动项、到期家务、库存、近期饮食和运动的固定优先级裁剪。
* **自动整理**：按保留策略定期整理旧记录；过期用餐记录清理后，一并回收已无引用的自动食谱，手工食谱与当前库存继续保留。

### 8. 🎙️ 声音、影像与表情：把生活说出来、拍下来

* **GPT Image、Gemini、Grok 生图**：支持文生图和图生图，能把当前生活状态、穿搭、场景和角色形象参考图整理成更适合出图的提示词；普通生活照是否带角色参考图由图片导演判断，创意衣橱手动生成按用户选择的方式执行，自动补衣固定使用角色图生图。各图片接口提供独立的文生图/图生图通道和模型配置，GPT Image 可手动填写接口支持的模型名称（如 `gpt-image-2`、`gpt-image-2.5`），不设置或发送 `quality` 参数；参考图编辑提交到 `/v1/images/edits`，JSON 使用 `images[].image_url`，multipart 使用 `image` 文件字段。Grok 通道兼容接口返回图片链接或 Base64 数据。
* **GPT Image 尺寸与异步任务**：支持文档所列档位规则的接口会自动匹配准确的像素尺寸，例如 1K、9:16 使用 `864x1536`；比例无法精确匹配时选择该档位内最接近的比例。支持异步图片任务的接口优先提交到对应的 `/async` 端点，按原任务编号查询并下载成品；未启用异步时自动使用同步端点，无需单独设置。任务被接收后立即保存任务编号和请求归属，不保存 API 密钥；查询暂不可用、等待超时或成品下载失败时保留原任务，后台及重启恢复只查询原编号，不重新提交或自动切换通道。静物改图等不需要角色身份的画面不会额外混入角色参考图。
* **Grok 图片接口**：文生图使用 `/v1/images/generations`，支持 `grok-imagine-image`、`grok-imagine-image-2.0`；图生图使用 `/v1/images/edits`，上述生成模型自动改用 `grok-imagine-image-edit`。单图参考提交为 `image.url`，多图参考提交为 `images[].image_url`，使用 Base64 data URL 保存原参考内容。1K、2K 档位和比例自动转换为文档支持的 `size`，不支持的比例选择最接近的尺寸；不发送 `aspect_ratio`、`resolution` 或 `stream`，无需额外配置。
* **普通聊天主动分享图片**：角色会结合自身性格、关系、当前生活状态、眼前事物和聊天节奏，判断是否自然产生“想让对方看看这个瞬间”的意愿；有独立画面价值时可直接分享，不需要用户先索要，也不靠关键词、固定场景或随机概率触发。视频仍沿用明确请求、引用图转视频或强动作/镜头场景的原有边界。
* **真实换装与图片试穿分离**：用户明确要求当前角色实际换装时，会先更新生活穿搭状态，再以已经保存的最终造型作为确认照唯一依据；同一条“换一套”请求不会在生图阶段被再次解释成另一套衣服、鞋饰或发型。只想看试穿效果或创作图片时，仍可临时指定视觉造型，不会改变当前生活状态。
* **生活套图**：明确要求“拍一套”或“多拍几张”时，默认后台生成 3 张、最多 6 张独立原图；整组保持人物、穿搭、场景和光线连续，局部失败可按位置重拍，不会重做其他成功照片。前一组已受理后，后台结合当前消息与原套图记录复核是否确实要求另外一组；普通接话、感谢或亲昵回应不会沿用旧要求重复生成，明确另拍同样场景仍可执行。
* **媒体后台交付**：单张生图、改图、套图和视频生成提交后独立执行，等待期间可以继续聊天。图片导演与实际生成不占用原工具轮次；后续聊天图片或表情包不会替换已提交请求的提示词、参考图或视频首帧。成品仍会送达，补发文字只在原请求仍是当前话题时发送，避免打断后续对话。
* **长总结与衣橱学习**：视频专业总结和视觉衣橱学习提交后在后台执行，等待期间可以继续聊天。视频与最多 6 张学习图片在提交时锁定，本地视频保留可用副本；总结成品和真实入库结果独立送达，不会提前声称已经完成。主动语音在合成后复检会话，期间收到新消息时放弃旧语音，也不会退回发送旧文字。
* **人物身份参考**：当前角色沿用既有人设与角色形象参考图；人设明确写出的稳定体貌会在单图、套图和视频首帧中保持一致，服装、姿势与镜头只改变其自然呈现。好友身份由关系档案、昵称和参考图共同确定。合影会独立绑定双方的外貌与穿搭，降低串脸、身份互换、比例漂移和服装串用。好友造型按会话和日期保持连续：适合当前场景时继续沿用，外出服回家后也可以暂时不换；居家服或睡衣进入户外、公共场合前会要求生成合适的新穿搭。
  合影中的人物 A/B 还会继承同一套人物事实边界；好友参考图用于身份与稳定外观，不会覆盖人设中已明确的称呼、性别或关系。
* **合影视频**：可直接引用已有合影生成视频，也可用当前角色与一位好友的参考档案重新生成双人首帧；普通“一起拍个视频”始终按新拍摄处理，只有明确要求让上一张动起来时才沿用上一张照片。视频保持双方身份与各自外观、穿搭连续，站位、互动、动作和镜头运动由视频导演按剧情决定；失败时保留并发送已生成的合影照片。
* **Grok 视频生成**：使用 `/v1/videos` 异步任务接口，模型名称可手动填写，支持 480p/720p/1080p 清晰度，并以 `input_reference` 提交首帧。首帧不超过 20 MB 时保留原图尺寸、格式和画质，只有超限时才在工作线程中生成小体积 JPEG 临时副本。视频在后台等待生成完成后发送，不拖住正常聊天。
* **自适应视频理解**：B站视频和普通视频统一按照配置使用本地 ASR 或必剪转写；视频素材只准备一次，音频转写会复用已下载视频或从中提取音轨，避免重复下载。画面会按时长和变化筛选关键帧，优先一次多图理解，避免固定逐帧串行调用。专业总结按实际议题提炼背景、论点、事实、数据、分析、风险和建议；实际内容章节保留素材时间定位，针对全片的“总结与参考建议”不显示时间轴。关键画面用于辅助理解但不插入专业总结成品，只有画面没有文字时也能继续总结。
* **火山引擎语音合成 2.0**：支持火山预置音色和控制台创建的声音复刻 2.0 音色；语义裁定会直接返回 `neutral`、`happy`、`light`、`sad` 或 `angry` 语音风格枚举，再转换为语速、音量和音调变化，不从自然语言情绪描述中猜测风格。插件只负责调用，失败时改用文字；只有当前消息的语音实际投递成功后才会隐藏重复文字，上一轮工具状态不会影响本轮回复，发送给适配器的内容保持为纯语音组件。普通聊天语音合成后复核话轮、撤回与回复版本，过期结果不再发送，也不提前写入已发送历史或语音节奏记录。复刻音色不读取本地命中缓存，控制台重新训练后下一次发送立即使用新音色；超过单次接口长度的文本会按自然标点拆分并合并为一条语音。
  使用前在火山引擎控制台取得 API Key，并从音色库复制音色 ID；声音上传、训练和重新复刻仍在火山控制台完成，插件不保存训练样本或训练任务。
* **语音智能切换**：由模型先判断“这句适不适合说出口”，再结合节奏门控和最近发送情况决定是否发语音。
* **实时通话（可选）**：启用后，`实时语音通话` 使用 WebSocket 全双工接口，`AI音视频通话` 使用 veRTC AI 音视频互动方案；两者共用 6186 网关，但模型和凭据分别配置。短链开关在本插件中独立配置，短链 API Key 复用“天气”中的柠柚接口密钥，服务不可用时自动回退完整邀请。点击并授权麦克风后，浏览器通过插件内置网关接通通话；AI 音视频模式还可按配置申请摄像头并向支持视觉理解的模型提供采样画面。通话会注入当前 AstrBot 人设、当前用户身份、目标关系、会话范围和精简生活上下文；是否先开口由发起通话的主模型结合当前话题、状态和关系决定，有自然由头才传入上下文相关开场，没有就先听用户说话，不使用固定寒暄。实时转写按“你/对方”发言轮次展示，通话结束后按轮次写入当前 AstrBot 对话历史，生活事件只保存状态摘要，不保存通话录音。实时通话内置结束工具始终可用；开启“允许实时通话调用工具”后，会把当前 AstrBot 已注册且可用的插件/MCP 工具直接交给通话模型，沿用原生权限与执行器，单次调用按超时设置收束，不包含再次发起通话的工具。另可启用火山实时对话官方联网能力：它使用融合信息搜索的独立 API Key，不复用语音、Tavily 或 AstrBot 工具密钥；唱歌能力仅在官方支持的 `1.2.1.1` 模型下启用。`1.2.1.1` 会自动切换到 O2.0 二进制事件协议，复用普通语音配置中的 API Key 和官方 O2.0 音色；其他模型继续使用新版 JSON 全双工协议。需要把 6186 端口通过 HTTPS 反向代理或公网映射，并在 `realtime_voice_call_config.public_url` 填写手机可访问的地址。
  > RTC 模式下，ASR 使用 `volc.seedasr.sauc.duration`，TTS/声音复刻使用 `volcano_bidirection` 的 `Credential.ResourceId` 与 `VolcanoTTSParameters`。当前请求体不需要 ASR/TTS AppId、AccessToken 或 Cluster；用户说话后 20 秒仍没有 Bot 音频时，页面会提示检查插件日志中的 ASR、LLM、TTS 状态和公网回调。
* **表情与动作意图**：记忆提炼时会记录情绪、动作和表情倾向，让后续表达更像角色自然反应，而不是只会打字。
* **表情轮换**：普通回复、主动互动和表情工具共用当前会话最近 5 次成功发送记录；刚用过的素材不再重复进入候选，候选不足时宁可不发，也不会强行重复。
* **工具状态表情**：在 OneBot/NapCat 上，图片、视频、套图、视频理解和联网检索等耗时工具会在用户原消息上标记处理中；同一轮全部工具、后台媒体和最终回复真实完成后，才统一标记成功或失败，其他平台自动跳过。

## 🚀 快速开始

1. **📦 安装并启用**
   - 在插件市场安装 `astrbot_plugin_daily_life`。

2. **⏰ 设置生成时间**
   - 默认是 `07:00`。
   - 可直接说“把每天生成时间改到 07:30”，由工具更新。
   - 这个时间既是每日生成时间，也是业务日边界。

3. **🧠 选择模型**
   - 生成模型负责完整日程、周计划和未单独指定的任务；“地点预选模型”只负责生成日程前整理地图查询意图，留空时使用 AstrBot 当前默认模型。
   - 穿搭模型、状态模型、复盘模型、邀约模型、视觉模型、记忆模型、闲时回复模型都可以单独指定。
   - 指定模型失败时会临时使用当前默认模型继续；指定模型恢复后会自动回到指定模型。

4. **🌦️ 配置天气和称呼**
   - 居住地由高德地图解析为天气城市和“家”的坐标，会影响天气、日程、穿搭和出行。
   - 修改居住地后会自动重建当前周计划、天气和当天生活背景；旧城市记录仍可作为历史回看，但不会继续充当当前附近地点或日程素材。
   - 如果平台无法稳定获取昵称，可在本地用户称呼映射里补充 `用户ID:称呼`，它会用于聊天记忆、邀约、备忘录、参考私聊、MemOS 和面板展示。

5. **🌱 生成第一天**
   - 直接说“重新生成今天”即可生成当前业务日完整生活背景。
   - 直接问“今天安排是什么”“Ta现在在干嘛”即可查询。

6. **🖥️ 打开仪表盘**
   - 在网页管理后台的插件详情页进入 `dashboard`。
   - 可查看状态、世界记忆、生活复盘、近期演化，也可以直接调整设置。

### 🔐 权限与隐私

- 普通生活状态、今日日程和天气可以正常查询；跨会话历史、世界记忆、偏好、生活事件、配置概览、每日复盘和存储统计只允许 AstrBot 管理员查看。
- 清空数据、重生成日程、修改每日生成时间和 B 站登录管理只允许 AstrBot 管理员执行；换装、刷新状态、地图路线、邀约、备忘和视觉衣橱等会改变或暴露角色生活信息的动作，仅允许管理员或私聊会话使用。
- 这里的“私聊会话”按消息场景判断，不等同于主人或联系人白名单。插件同时服务多个私聊联系人时，他们会共同影响同一角色的全局生活状态；需要限制使用对象时，应在 AstrBot 的平台接入或权限配置中控制联系人范围。
- 承诺按创建会话隔离。普通用户只能查看和修改当前会话创建的承诺；旧记录若没有来源会话，只允许管理员维护。
- 聊天模型只负责提出结构化生活动作，插件会再次执行权限、归属、参数和状态校验后才提交；数据库迁移、事务、任务恢复、媒体投递和权限判断始终由确定性代码完成。
- 正常运行建议使用 AstrBot 的 `INFO` 日志并关闭 trace。需要排障时再临时开启 `DEBUG`，排障结束后及时恢复，避免聊天、地点、关系和日程上下文长期写入日志。

### 🎧 安装本地 ASR 依赖

1. 打开 AstrBot 管理面板，在左侧进入 **更多 → 平台日志**。
2. 点击平台日志右上角的 **安装 Pip 库**。
3. 在“库名”输入框中填写：

   ```text
   funasr>=1 modelscope>=1 torch>=2 torchaudio>=2
   ```

4. “强制 PyPI 软件仓库链接”可以留空；如需使用自定义镜像，再填写对应地址。
5. 点击 **安装**，等待平台日志显示安装成功后重启 AstrBot。
6. 本地 ASR 模型会在第一次转写时自动准备；准备失败时插件会继续使用必剪转写。

## 💬 自然语言使用

开启工具调用后，不需要记住一串机械指令。自然语言提供的是生活线索、查询目标或明确调整；最终仍由角色状态、当天背景和当前上下文共同决定。

| 你可以这样说 | 会触发的能力 |
| :--- | :--- |
| “下午一起去看电影吧” | 判断邀约是否能打断今天的计划，并决定接受、改约或合并进后续日程 |
| “Ta现在在干嘛？” | 查询当前状态和正在发生的时间轴 |
| “今天安排是什么？” | 查询当前业务日完整日程、天气和穿搭 |
| “看看本周计划/世界记忆/最近历史” | 查询周计划、世界记忆、历史摘要等 |
| “重新生成今天，今天少出门” | 按补充要求重新生成当前业务日 |
| “保持日程，只换一下现在的穿搭” | 保留日程并更新穿搭判断 |
| “你这身适合出去玩吗？” | 结合当前穿搭、天气和外出安排判断是否合适 |
| “今天适合出门吗？” | 结合天气、日程、地点倾向和当前状态回答 |
| “今晚早点睡吧” | 作为聊天记忆、承诺或生活倾向被参考，不需要硬性的睡觉指令 |
| “把每天生成时间改到 07:30” | 更新每日生活背景生成时间 |
| “明天记得去超市买牛奶” | 写入明日备忘或未来承诺 |
| “生成一套适合春天去书店的浅色通勤穿搭，带自然锁骨发和裸色短甲” | 按本次需求生成生活化造型，视觉核对后加入创意衣橱候选 |
| “用角色参考图生成两套适合周末出门的造型” | 使用图生图生成两张独立候选；缺少图生图条件时明确失败，不自动切换模式 |
| “把 3 号承诺延期到周末/完成 3 号承诺” | 管理承诺状态 |
| “查一下上海天气” | 查询指定城市天气；留空查询居住地解析出的城市天气 |
| “附近有什么适合安静坐一会儿的咖啡店？” | 按居住地解析出的城市和当前上下文搜索真实地点，返回名称、地址、距离、营业信息和地点编号 |
| “从祖庙去千灯湖怎么走？比较一下几种方式” | 比较步行、骑行、驾车和公交路线；驾车结果会结合附近实时路况 |
| “详细看看刚才第二家店” | 使用上一次地点搜索返回的地点编号查询电话、营业时间、评分等详情 |
| “从祖庙出发，两小时去岭南天地和一家甜品店，帮我排一下” | 在时间预算内自动选择地点、排列停留顺序并核算逐段路线，不要求手工填写坐标 |
| “生成今天复盘” | 查看或生成每日复盘 |
| “把刚才转成图片的内容发成文字版” | 将最近一条文本转图像回复的原文通过 QQ 合并转发发送 |

## 🌐 联网搜索

插件提供一套独立于 AstrBot 默认网页搜索的联网能力：Tavily 负责网页搜索、正文提取、站点映射、站点抓取和研究任务，Grok 只负责 X 平台原生搜索。直接用自然语言说明要搜索、核实、读取或研究的内容，聊天模型会选择合适的工具。

### 1. 🔑 准备 Tavily 密钥

1. 在 [Tavily 控制台](https://app.tavily.com/) 创建 API Key。
2. 打开插件设置的“联网搜索”分组。
3. 在“Tavily 接口密钥”中填写一个或多个 `tvly-...` 密钥，不要添加 `Bearer` 前缀。
4. 开启“启用联网搜索”并等待设置自动保存。

Tavily 密钥只从 `search_config.tavily_api_keys` 读取，不会读取 AstrBot 自带网页搜索中的 Tavily 密钥。填写多个密钥时，每次创建 Tavily 请求会按顺序轮换；轮换用于分摊调用，不代表某个密钥失败后会自动改用下一条重试。启用本插件联网搜索后会自动移除 AstrBot 默认网页搜索工具，因此需要网页能力时应先填好 Tavily 密钥再开启。

“X 平台搜索”模型不是 Tavily 普通网页能力的必填项：不配置时，Search、Extract、Map、Crawl 和 Research 均可正常使用；配置支持 Grok 官方 `x_search` 的模型后，才可使用 X 搜索和 `both` 混合搜索，深度网页搜索也可用该模型规划补充查询。

### 5. 🧭 Quick 与 Deep

`quick` 用于单个问题，首轮使用 Tavily Fast Search，一般只执行一次主查询；向聊天模型回填最多 2000 字、5 条证据。适合当前事实、单条新闻、简单资料和普通问答。

`deep` 用于需要多来源核验的问题，首轮使用 Tavily Advanced Search。首轮证据不足且已配置搜索模型时，模型会规划独立的补充问题，并在剩余总时间内并发执行；补充查询总数受“补充搜索数量”限制，取得强证据、没有新增来源或时间不足时会提前停止。未配置搜索模型时，Deep 仍会完成一次 Tavily Advanced Search，但不会生成补充查询。Deep 向聊天模型回填最多 6000 字、8 条来源。

模型第一次调用时应提交一个完整问题，不需要一次生成多个近似搜索。工具结果会返回 `quality`、`missing_aspects`、`search_guidance`、`queries_executed` 和 `session_id`：证据为 `strong` 且没有缺失项时应停止；只有仍有缺失、来源冲突、用户追问或明确的新问题时才继续。

### 6. 📅 搜索来源、日期和参数

`source_scope` 决定来源：

* `web`：只使用 Tavily 网页搜索，也是默认值。
* `x`：只使用 Grok 官方 `x_search`，不会回退到 Tavily 网页。
* `both`：并发执行 Tavily 网页搜索和 Grok X 搜索，合并内容与引用。

日期限制针对**网页发布日期**，不代表事件发生日期。`time_range` 只在用户明确要求近期内容时使用，支持 `day`、`week`、`month` 和 `year`；`start_date`、`end_date` 使用 `YYYY-MM-DD`，填写后优先于相对时间范围。查询旧事件时不要随意使用 `year`，否则会排除更早但关键的原始来源。同一天的开始和结束日期会在发送给 Tavily 时自动扩展，避免 Tavily 拒绝相同日期。

其他 Search 参数：

* `topic`：`general` 适合一般资料，`news` 适合新闻，`finance` 适合金融信息。
* `include_domains` / `exclude_domains`：优先或排除指定域名；Tavily 精确限定站点应使用域名列表。
* `country`：只在 `general` 主题下用于国家或地区偏向。
* `include_raw_content`：需要核对页面正文时返回清洗内容，会增加结果长度和调用消耗。
* `include_images`：返回相关图片；`include_image_descriptions` 在此基础上请求图片描述。图片结果会单独返回 `images`、`image_quality` 和 `image_guidance`，不与文字证据质量混用。
* `auto_parameters`：允许 Tavily 根据问题自动选择部分搜索参数，适合边界不明确的复杂问题。
* `exact_match`：只保留包含查询原文的结果，适合精确短语，可能明显降低召回率。
* `platform`：主要用于 X 平台范围提示；Tavily 网页站点限制应使用 `include_domains`。

### 7. 🕸️ Extract、Map 与 Crawl

图片搜索取得文字来源但没有可用图片时，插件会在同一总时间预算内自动读取最多两个高相关 Tavily 页面补充图片，不需要模型重复发起多个近似搜索。工具结果包含图片后，下一步应直接调用 `send_message_to_user` 发送，不要继续重复搜索。

`life_web_fetch` 读取单个普通 URL 时优先调用 Tavily Extract。正文提取失败后，会在同一总时间预算内自动执行 URL 定向 Search：`mode=page_extract` 表示确实取得页面正文，`mode=search_fallback` 表示只取得相关搜索资料，后者不能表述为已经逐字读完原文。

批量 URL、指定相关性问题、要求图片、favicon 或特殊格式时会使用批量 Extract。每个地址最多返回 1 至 5 个相关片段；成功内容放在 `results`，失败详情保留在 `failed_results`，不会因为部分成功而丢失失败原因。

`life_web_map` 只发现链接，可使用路径和域名的包含/排除规则控制范围。`life_web_crawl` 会继续读取页面正文，支持相同筛选规则、图片、favicon、`basic`/`advanced` 提取深度以及 `markdown`/`text` 格式。只想留在当前站点时应明确要求不跟随外部域名。

### 8. 🔬 Research 后台任务

Research 采用后台轮询，不阻塞 AstrBot 主事件循环；任务同时写入生活插件已有的可恢复队列，插件重启后会按原会话恢复未完成任务：

1. `life_web_research` 创建任务并返回 `pending`、`task_id` 和 Tavily `request_id`。
2. 插件按“研究状态轮询间隔”在后台检查任务状态。
3. `life_web_research_status` 使用 `task_id` 返回 `pending`、`completed`、`failed`、`cancelled`、`error` 或 `timeout`。
4. 任务完成前不能声称报告已经生成；完成后再依据研究输出和引用回答。
5. 研究任务绑定创建它的会话；其他会话即使拿到任务编号也不能读取报告。

Research 支持 `mini`、`pro`、`auto` 模型，`short`、`standard`、`long` 输出长度，`numbered`、`mla`、`apa`、`chicago` 引用格式，域名包含/排除以及可选 JSON Schema 结构化输出。

### 9. 🗂️ 结果、缓存与日程灵感

每条用户消息建立一个搜索会话，共享“搜索总超时”和已有证据。查询词与参数完全相同时直接复用同轮结果；同一搜索上下文已经取得强证据时，会停止没有新增目标的重复搜索。跨消息的完全相同查询按 TTL 缓存，缓存键包含搜索深度、来源、最终日期、域名、图片和其他实际参数；同时发生的相同搜索或网页读取只执行一次上游请求。失败结果不写入缓存，模型提出不同查询或不同参数时不会被普通缓存阻止。

搜索日志会显示深度、范围、最终日期、引擎、来源数、耗时和查询内容。纯网页结果显示 `Tavily`，纯 X 结果显示 `Grok`，混合结果显示 `Grok+Tavily`；缓存命中会在工具结果中标记 `cached=true`。

开启“日程使用联网灵感”后，今日生活和周计划只接收带可核验来源的结果：弱证据直接忽略，部分证据只作为生活背景灵感，强证据正常参考。周计划的搜索与生成共用同一操作锁，避免并发操作重复搜索。

## 🧠 MemOS 外部长期记忆

插件可以连接 MemOS 托管服务，把外部长期事实、偏好和纠错作为隐藏参考注入聊天。

默认是**只检索，不写入**：聊天前短暂等待 MemOS 返回相关记忆，超时或失败就跳过，不影响正常回复。开启精选同步后，只会把本插件已经判断值得长期复用的摘要、偏好、关系点、备忘录和记忆纠错异步同步过去，不会把每一轮聊天都塞进外部记忆。

内置记忆更像Ta自己的生活小抽屉，负责当天状态、关系印象、复盘和世界记忆；MemOS 更像可选的外部长记忆书架，适合和其他记忆系统共享稳定事实。

<summary><b>🧺 几个容易忽略的小设置</b></summary>

1. **生成时间不是普通闹钟**
   - 它同时决定每日生活背景生成时间和业务日边界。
   - 例如设置为 `07:00`，那么凌晨 `02:00` 仍会被视作前一天的深夜延续。

2. **穿搭模型只负责实时判断**
   - 完整日程生成里的穿搭跟随生成模型。
   - 自主生活状态更新、手动重置保持、外出适配判断等实时场景会使用穿搭模型。

3. **创意衣橱的生成方式**
   - 在“生活背景 → 创意衣橱”中开启功能，并选择默认的“文生图”或“图生图”；衣橱面板的生成方式会跟随这个默认值。
   - 手动文生图不读取角色参考图；图生图必须具备可用通道和已启用的当前角色参考图，缺少条件时保留待办。自动补衣固定使用角色图生图。
   - 生成在后台进行，等待期间可以继续聊天；请求结合本次需求、居住地天气和已有审美，不读取联网灵感或固定风格池。手动请求的数量仍为本次图片数，每张图独立识别后才进入候选库。
   - 自主衣橱每分钟检查事实，必要时在后台判断天气、活动与可穿衣物。先保留合适穿搭和组合已有单品，再确认已有候选，确有缺口才补衣；同一缺口跨日沿用任务编号，自动补衣两次提交至少间隔 24 小时。
   - 自动补衣先通过完整衣物识别及用途复核，再正式纳入数字衣橱；不会直接改变当前穿搭。手动生成及导入默认为灵感候选，可以通过聊天明确纳入衣橱。
   - 衣物分别记录正式拥有、实际穿着、干净、待洗、清洗、晾晒和收纳状态。洗护中的衣物不可自动换上，正在穿的衣物不能送洗；洗护按后台观测推进，停机时间不会被补写为已完成。
   - 自身审美来自角色人设和跨日穿着经历，用户反馈作为单独参考。同一穿着回执只计一次；自己的经历至少三个独立回执且跨两日才形成软偏好，有新证据时可修订同来源偏好。历史照片和视频继续使用对应时刻的外观。
   - 自主判断依赖已开启的生活实况及内部行动；自动补衣另需开启创意衣橱、角色参考图及可用图生图通道。衣物归属和洗护属于角色的数字生活记录。
   - 慢速图片接口建议将通道超时设为 `300` 秒以上；超时后上游仍可能完成图片，但插件无法再取得该次同步响应。

4. **闲时回复默认克制**
   - 它不会在普通聊天时立刻抢话。
   - 只有会话安静超过配置时间，且通过模型裁定，才可能自然续一句。

5. **私聊回访建议谨慎开启**
   - 开启后会先等待 `private_idle_minutes` 设置的私聊静默时间，再根据关系档案、带时间的近期消息和当前生活状态判断是否自然私聊。
   - 适合强陪伴场景，不适合只想安静记录生活背景的场景。

6. **地图服务需要服务端 Key**
   - 使用[高德地图 Web 服务](https://lbs.amap.com/api/webservice/create-project-and-key)。在“生活实况 → 地点与出行”填写高德 Web 服务 Key 和居住地，无需选择地图服务商。
   - 天气城市、地点搜索范围、公交路线城市和“家”的坐标全部以高德的解析结果为准。
   - 天气不再提供独立的默认城市，也不会从人设猜测或回退到其他城市；地址或 Key 缺失、解析失败时，居住地天气和地图自然语言工具会明确保持不可用。
   - 关闭生活实况或地点与出行时，仍可用已填写的现实居住地查询天气；更换居住地会立即清除当前生活背景中的旧天气，再异步刷新。
   - 地点搜索、路线比较、地点详情和限时出行规划由聊天模型按需调用；输入提示以及高德可用时的实时路况仅作为内部辅助，不需要单独操作。
   - 公交路线优先采用地图响应中的线路类型显示为公交、地铁或混合换乘；接口未提供足够明细时显示“公共交通”，不会由模型猜测线路。
   - 工具结果不向模型暴露地点坐标。没有可靠的出发地时，模型应先询问，不会猜测用户当前位置。
   - 未填写高德 Key 时会隐藏地图自然语言工具，并使用默认出行时间估算，不会阻止日程生成。

7. **不再依赖模板抽签**
   - 主题、心情色彩、日程类型、穿搭风格和发型都由模型结合人设、近期惯性、天气、记忆和目标自动决定。
   - 日程联网结果只是现实参考，不会变成必须执行的固定脚本或硬性清单；创意衣橱不读取这类结果。

8. **没有日程时不会硬编**
   - 当前业务日没有生活记录时，会注入防编造隐藏约束。
   - 需要完整生活背景时，可以直接说“重新生成今天”，或在面板里重生成今日。

## 🧩 同作者插件

| 插件 | 关系 | 作用 |
| :--- | :--- | :--- |
| `astrbot_plugin_daily_share` | 姐妹插件 | 把见闻、热搜、心情、知识、推荐、图片、语音或视频自然分享到私聊或群聊 |

两个插件可以独立使用，也可以放在一起：一个负责“Ta正在怎样生活”，一个负责“Ta把路上拾到的见闻分享给你”。

联合运行时，生活插件通过入口公开分享专用生活上下文、联网检索证据、图片、视频、语音和外部主动行为记录能力：

- 分享插件读取生活上下文时只调用 `get_share_context(target_umo)`。该入口提供当天状态、天气、穿搭、日程、目标关系、会话摘要、事件、约定、生理节律、七日节律趋势，以及提炼后的关注事项、表达偏好、互动方式、互动反馈和熟悉用语。
- `current_facts` 提供当前自主活动的真实执行状态和已观测身体字段，不导出动作载荷、生命内核或私人目标；暂停、待结算不代表完成。更换居住地而背景尚未刷新时 `valid=false`，旧生活背景不参与分享。
- `get_share_chat_style(scene="")` 独立提供聊天表达总开关状态和配置中的短句风格软偏好，不依赖当天日程，不返回私聊记忆、聊天长度、分段发送或标点清洗规则。`scene="qzone_post"` 将同一偏好适配为单条公开说说的语气、节奏、自然分段和展开尺度，不固定字数、行数或标题模板；默认场景保持原软偏好。daily_share 的 QQ 空间说说、自动评论和回评固定使用该能力，不再提供独立表达开关或说说格式，也不复用普通分享格式；生活插件关闭表达或暂不可用时，分享插件保留自然公开表达，不恢复作文式模板。公开隐私、角色事实和评论回复对象仍由分享插件约束。
- `qzone_comment`、`qzone_reply` 场景分别适配评论和接话；目标表达习惯仍按联系人隔离，分享插件只选长期语气、习惯和避免项。`prepare_share_expression(text, scene=...)` 可检查公开说说的自然程度与展开尺度，或为 `share_voice` 按原文语义选择情绪与声音风格；不读取私聊上下文，不因语音检查改写原文。
- 分享上下文按目标精确隔离：私聊只返回当前联系人关系、当前会话摘要和与该联系人相关的经历；群聊不返回私聊关系，群聊经验使用当前群号作用域。
- QQ 空间等公开目标只返回适合公开使用的角色状态和无人物关联、来源为日常计划的生活片段。
- 分享专用入口不返回原始回复、证据、消息与数据库 ID、纠错记录、健康检查或内部治理数据；互动反馈只输出聚合数量和结论。
- 图片、视频和语音生成期间会持有外部调用租约；插件终止或重载会先等待正在执行的公开调用结束，超过 10 秒排空期限时取消旧运行时中的剩余调用并等待其完成清理。
- daily_share 不单独指定文生图、图生图模型，生活插件按参考图选择生成方式，从对应配置的第一个可用通道开始；受理前失败依次容错，受理后只查询原任务，不因超时重复生成。
- `generate_share_image_task`、`generate_share_video_task` 接收稳定 `task_key`，对应 `get_share_image_task`、`get_share_video_task` 返回 `pending`、`ready`、`failed` 或 `missing`。任务受理即持久保存原编号及非敏感通道引用，恢复使用当前配置凭据；相同编号不重复提交，成品只返回外部拥有者，不进入私聊投递队列。发布续接、静默时段和过期文案由分享插件管理。
- 联网检索由生活插件统一选择搜索策略和提供商；姐妹插件只提交主题、资料类别和目标会话，不访问搜索内部服务。
- 其他插件已经成功发送的主动内容可以回传为外部活动，并按现有 MemOS 设置决定是否同步长期记忆。
- QQ 空间等公开活动通过 `record_public_activity(receipt)` 回传 `event_id`、`scene`、`content` 和原 `occurred_at`，按事件编号去重并进入生活事件；不创建私聊记录，不重复扣社交电量，也不结算其他生活动作。支持说说、评论和回评场景。
- 插件禁用、未初始化或正在终止时拒绝新的外部调用，不会让已关闭的媒体或数据库服务重新工作。

这些能力是通用插件协作接口，`daily_life` 不导入也不依赖 `daily_share`；未安装姐妹插件时全部生活功能保持不变。

## 🧪 测试与回归

模型请求保留固定规则与真实历史前缀，实时生活背景放入 AstrBot 的本轮临时内容块，保存历史时自动排除。当前状态仍逐轮更新，不复用旧模型回答；这不需要新增配置。`page/status` 的 `model_cache` 返回当前插件运行期的聊天与内部调用用量，`cached_token_ratio` 按接口报告的缓存 token / 输入 token 汇总，缺少命中字段时为 `null`。配置切换沿用统计，插件重载后重新累计；是否实际命中还取决于所选接口、模型及缓存保留策略。

在插件目录下运行：

```bash
PYTHONPATH=. pytest -q -o python_files='test*.py' tests
python3 -m compileall -q .
python3 -m json.tool _conf_schema.json >/dev/null
```

`pytest` 是项目的标准测试入口；现有测试文件使用 `test*.py` 命名，命令显式指定发现规则，避免默认规则漏掉测试。不要直接依赖默认的 `unittest discover`，否则可能漏掉异步、参数化和项目专用 fixture。测试会按完整配置路径验证设置解析闭环；列表模板使用 `分组.*.字段` 记录，避免不同分组下的同名字段互相掩盖。

前端脚本检查：

```bash
find pages/dashboard -type f -name '*.js' -print0 \
  | xargs -0 -n1 node --check
```

## 🌰 生活片段示例

**场景 A：出门前的小判断**

> 生活背景：午后有外出安排，天气微热。  
> Ta的判断：当前穿搭是轻便休时风，适合短途出门，只需要把头发重新扎好，不必整套换装。  
> 后续影响：面板记录“保持当前穿搭，轻微整理发型”，聊天时也会自然带出“正准备出门”的生活感。

**场景 B：群聊里的安静观察**

> 生活背景：Ta正在看综艺，注意力半开放。  
> 群聊消息：群里有人聊到一个Ta有点熟悉的话题。  
> Ta的判断：看见了，但当前话题已经有人接得很好，Ta暂时不插话，只留下“扫过但未回应”的主观痕迹。  
> 后续影响：几分钟后如果有人继续这个话题，之前扫过的内容可能被重新激活。

**场景 C：夜里慢慢睡去**

> 生活背景：今天社交消耗偏高，睡眠债也有一点。  
> 消息打断：普通消息不足以叫醒Ta，强相关消息可能让Ta短暂浅醒。  
> Ta的状态：从浅休息进入浅睡眠，再慢慢沉到深度睡眠。  
> 后续影响：第二天体力、心情和日程倾向会自然接续，而不是重新从满格开始。
